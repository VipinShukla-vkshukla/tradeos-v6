## Data Flow

### Core tabs (hardcoded)
```
Supabase table
    └─→ lib/supabase.ts queries.*()
            └─→ Tab component (useEffect on mount)
                    └─→ DataGuard (loading/empty/error)
                            └─→ Chart or Table component
```

### Custom tabs (auto-generated by SmartTabGenerator)
```
SmartTabGenerator clicks "Create"
    └─→ /api/profile (samples all tables, returns column stats)
            └─→ For each table with data: addView({ viewType: 'auto', table })
                    └─→ layoutStore.addViewToTab(tabId, viewId)
                            └─→ viewStore.addView() → localStorage + Supabase custom_views

User navigates to custom tab
    └─→ CustomTabView reads layoutStore.getTabViews(tabId)
            └─→ For each view with viewType='auto': renders AutoDashboard
                    └─→ /api/profile?table=X (10s timeout, never hangs)
                            └─→ lib/autoViz.ts generateVizPlan() [rule engine, no AI]
                                    └─→ queryTable() for each chart's columns
                                            └─→ AutoChart renders the right chart type
                                /api/ai/analyze [async, 20s timeout]
                                    └─→ DeepSeek/Anthropic/OpenAI (reads system_config)
                                            └─→ AIInsightPanel (narrative + anomalies)
```

### Manual view builder (ViewWizard)
```
User clicks ⊞ in tab bar
    └─→ ViewWizard opens
            Step 0: Name + target tab selection
            Step 1: /api/schema → table picker
            Step 2: Column selector + AI prompt → /api/ai/suggest → DeepSeek
            Step 3: Join builder (FK detection from column names ending in _id)
            Step 4: Summary + save
    └─→ viewStore.addView({ viewType: 'table' })
            └─→ CustomTabView renders LiveDataView
                    └─→ queryTable() with selected columns/filters/joins
```

### Mutations (write paths)
```
Brain Engine "Approve" button
    └─→ lib/api.ts brainApi.approve(id)
            └─→ /api/brain/proposals/[id] PATCH
                    └─→ Supabase brain_proposals.status = 'APPROVED'

Data Management inline edit
    └─→ lib/api.ts configApi.update(key, value)
            └─→ /api/config/[key] PATCH
                    └─→ Supabase system_config.value = new value
                    └─→ Supabase config_change_log INSERT (audit trail)
```

## State Management

### layoutStore (Zustand + localStorage `tradeos-layout`)
Owns: tabs array, activeTabId, tab→viewId assignments, chartBuilderOpen

Key methods:
- `addTab(tab)` — adds a custom tab
- `removeTab(id)` — removes tab, resets to 'performance'
- `renameTab(id, name)` — renames
- `addViewToTab(tabId, viewId)` — assigns view to tab
- `getTabViews(tabId)` — returns viewId array for a tab
- `merge()` — on load, always restores core tab names from CORE_TABS (prevents stale localStorage)

### viewStore (Zustand + localStorage `tradeos-views`)
Owns: all DynamicView/ExtendedView objects, wizard state

Key methods:
- `addView(view)` — saves to localStorage immediately + async Supabase
- `setViews(views)` — used by page.tsx to merge (not replace) server views
- `openWizard(existing?)` — opens ViewWizard with blank or existing draft
- `updateWizardDraft(updates)` — live wizard state

View types:
- `viewType: 'auto'` — auto-generated by SmartTabGenerator, rendered by AutoDashboard
- `viewType: 'table'` — manual wizard view, rendered by LiveDataView

## API Routes

| Route | Method | Auth | Purpose |
|---|---|---|---|
| `/api/profile` | GET | Service role | Column stats for any/all tables |
| `/api/ai/suggest` | POST | Service role | Column suggestions for ViewWizard |
| `/api/ai/analyze` | POST | Service role | Narrative + anomaly insights for AutoDashboard |
| `/api/views` | GET/POST | Service role | List/create custom_views |
| `/api/views/[id]` | GET/PUT/DELETE | Service role | Single view CRUD |
| `/api/brain/proposals/[id]` | PATCH | Service role | Approve/reject/rollback brain proposals |
| `/api/config/[key]` | PATCH | Service role | Update system_config value |
| `/api/schema` | GET | Service role | Table + column list for ViewWizard picker |

All routes use `SUPABASE_SERVICE_ROLE_KEY` (server-side only, never NEXT_PUBLIC_).

## Key Design Decisions

**Why no FastAPI?**
Reads go direct Supabase (anon key, browser-safe). Mutations go through Next.js API routes (service role, server-side). FastAPI would only be needed for a live order execution surface — which runs via Kite Connect through GitHub Actions.

**Why autoViz.ts is rule-based, not AI?**
Charts must render instantly on load. AI insight is async and non-blocking — charts appear immediately, AI narrative follows 2-5 seconds later.

**Why views are localStorage-first?**
Auto-generated views are saved to localStorage immediately. Supabase `custom_views` is secondary persistence. On load, server views are merged into local, never replacing local. This prevents empty tabs on restart when Supabase save failed.

**Why tabs use `name` not `label`?**
The original `types/registry.ts TabConfig` uses `name`. The layoutStore `merge()` function always restores core tab names from `CORE_TABS` on load, preventing stale localStorage from showing "Tab" labels.
